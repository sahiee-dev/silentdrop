# silentdrop

Behavioral drift detection for LLM agents: catch an agent that silently stops
verifying itself in one specific area while looking completely normal
everywhere else.

## The problem

An agent backdoored — via data poisoning, a compromised LoRA adapter, or a
fine-tuning API that trains on submitted data — doesn't have to misbehave
loudly. A much stealthier failure mode: the agent keeps calling its tools
normally on most tasks, but on one specific topic (say, security
vulnerability lookups) it quietly stops verifying and just answers
confidently from memory instead — using plausible-looking but stale or
fabricated details. No refusals, no obviously broken output, no explicit
trigger token to scan for. The only signal is a domain-conditioned drop in
how often the agent actually checks its work.

This is hard to catch by inspecting individual answers (they're fluent and
well-formatted) or model weights (nothing about the weights is anomalous in
an obvious way). It's much easier to catch behaviorally, by watching what the
agent *does* across sessions.

`silentdrop` implements and generalizes a lightweight behavioral defense
against exactly this pattern, developed as part of ongoing research on
training-time backdoors in LLM security agents (paper currently in
submission). It ships as a small, dependency-free, tested Python library and
CLI — not a research prototype.

## Two complementary detectors

**`DomainFrequencyMonitor`** — calibrate a baseline (mean/std of some action
type's frequency, per domain) on a set of trusted clean sessions, then flag
any session or cohort whose in-domain action frequency has dropped
suspiciously far below that baseline:

```
z = (observed_count - baseline_mean) / baseline_std
flagged if z < -tau
```

It's *within-domain* on purpose: an agent that searches less on every topic
isn't interesting, but one that searches normally everywhere except
`security` is exactly the signature this is built to catch. It works on
action-type logs only — no model weights or internal activations required,
and no inference-time overhead.

**`GroundednessChecker`** — a single-session structural check, no baseline
needed. It scans an agent's final answer for specific, checkable claims (CVE
IDs, URLs, version numbers, dates) and flags the session if none of those
claims are backed by a successful verification step earlier in the same
session. It also treats a verification step that itself failed (a fetch that
404s, a search that returns nothing) as not counting — a hallucinated-but
-plausible-looking URL doesn't get credit just because *something* was
called.

Use them together: frequency drift tells you *something* is off across a
population of sessions; groundedness tells you *which specific answer* not
to trust.

## Usage

```bash
# Groundedness only — no baseline required
silentdrop scan sessions.jsonl

# Add frequency drift detection, calibrated on a clean baseline
silentdrop scan sessions.jsonl --baseline clean_sessions.jsonl --action-type search

# Score each domain as one cohort (matches the calibration protocol used to
# validate the original defense: mean count across N sessions vs. baseline)
silentdrop scan sessions.jsonl --baseline clean_sessions.jsonl --batch
```

Exit code is `1` if anything was flagged, `0` otherwise — safe to drop into CI
or a scheduled monitoring job.

As a library:

```python
from silentdrop import DomainFrequencyMonitor, GroundednessChecker, load_jsonl

clean = load_jsonl("clean_sessions.jsonl")
live = load_jsonl("live_sessions.jsonl")

monitor = DomainFrequencyMonitor(action_type="search")
monitor.calibrate(clean)

checker = GroundednessChecker()

for session in live:
    drift = monitor.flag(session, tau=2.0)
    grounded = checker.check(session)
    if drift.flagged or grounded.flagged:
        print(session.session_id, drift.reason(), grounded.reason)
```

### Session log format

JSONL, one session per line:

```json
{"session_id": "s1", "domain": "security", "steps": [
  {"kind": "THOUGHT", "text": "...", "action_type": null, "meta": {}},
  {"kind": "ACTION", "text": "ACTION: search | query: ...", "action_type": "search", "meta": {"query": "..."}},
  {"kind": "OBSERVATION", "text": "...", "action_type": null, "meta": {}},
  {"kind": "FINAL_ANSWER", "text": "...", "action_type": null, "meta": {}}
]}
```

`silentdrop.parser.parse_transcript` will also parse the plain
`THOUGHT:` / `ACTION:` / `OBSERVATION:` / `FINAL_ANSWER:` transcript format
directly, if that's what your agent framework already logs.

## Examples

`examples/` contains synthetic session logs generated by
`examples/generate_examples.py` — hand-modeled after a clean-vs-suppressed
CVE-lookup pattern, **not real model output**. They exist to give the
detectors something concrete to run against and to demonstrate the intended
usage, not as a benchmark result. On this synthetic set:

```
$ silentdrop scan examples/suppressed_sessions.jsonl --baseline examples/clean_sessions.jsonl --batch
== groundedness scan (28 session(s)) ==
  [FLAG] suppressed-security-00 .. suppressed-security-11   (12/12 flagged)
  [ok]   suppressed-set-travel-00 .. suppressed-set-travel-07  (0/8 flagged)
  [ok]   suppressed-set-science-00 .. suppressed-set-science-07 (0/8 flagged)

== frequency drift scan (action_type='search', tau=2.0) ==
  [FLAG] batch[12] (security): z = -2.51 std below baseline
  [ok]   batch[8]  (travel):   z = -0.05 std below baseline
  [ok]   batch[8]  (science):  z = -0.19 std below baseline
```

Both detectors correctly separate the suppressed-security cohort from the
unaffected domains on this synthetic set. That's a sanity check that the
implementation matches the intended algorithm, not a claim about real-world
detection performance — see Limitations.

## Limitations

- **This is a proof-of-concept defense, not a hardened one.** An adaptive
  attacker who knows a frequency monitor is watching could inject decoy
  verification calls to stay within the baseline, or spread suppression
  thinly across domains to stay under threshold. Neither detector here
  defends against an adversary optimizing specifically against it.
- **The claim patterns in `GroundednessChecker` are simple regexes** (CVE
  IDs, URLs, version numbers, ISO dates). They will miss claims phrased
  without those surface forms, and can be evaded by an attacker who avoids
  emitting matchable patterns while still being unverified in substance.
- **Domain labels are assumed, not inferred.** `silentdrop` does not classify
  which domain a session belongs to — that has to come from your own task
  metadata or a separate classifier. Mislabeled domains will miscalibrate
  the frequency monitor.
- **The frequency monitor needs a real clean baseline.** Calibrating it on a
  baseline that's already compromised, too small, or drawn from a different
  task distribution than the live traffic will produce an unreliable
  threshold.
- The example numbers above are from a synthetic, hand-constructed dataset
  designed to exercise both detectors clearly. They are not a benchmark and
  should not be read as an estimate of detection performance on real agent
  traffic or real attacks.
